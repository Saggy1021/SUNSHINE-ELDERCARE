# PHASE 19G — R2 REMEDIATION REPORT

## 1. Problem Statement
During the final verification of the Phase 19G Google Drive temporary storage provider, a severe architectural limitation was exposed. Google Drive does not support native S3-style presigned URLs for files secured in a Restricted folder without altering their permissions (which compromises security). Therefore, downloads had to be buffered and proxied directly through the Next.js Serverless runtime. 

Vercel Serverless Functions impose a strict **4.5 MB maximum response payload limit**. Consequently, any attempt to download a legitimate 10MB medical document through the Google Drive proxy resulted in a fatal HTTP 500 Payload Too Large crash.

## 2. Remediation Architecture
To bypass this limitation, the application architecture was pivoted to utilize **Cloudflare R2** as the primary production document storage provider. R2 provides full S3 compatibility, zero egress fees, and critically: secure, short-lived, presigned download URLs.

## 3. Remediation Implementation
1. **R2StorageProvider**: Implemented a new provider (`lib/services/storage/r2-adapter.ts`) using `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner`.
2. **Download Redirection**: Modified the core download route (`app/api/documents/download/route.ts`). It now detects if a `StorageProvider` returns a remote HTTP presigned URL and issues a fast `HTTP 307 Temporary Redirect` to the URL.
3. **Bandwidth Offloading**: By issuing a 307 Redirect, the user's browser fetches the 10MB file directly from Cloudflare's edge CDN, instantly bypassing Vercel's 4.5MB Serverless limit while retaining total IDOR and RBAC security at the application boundary (since the redirect only occurs *after* authorization).
4. **Environment Realignment**: Shifted `.env` to expect `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, and `R2_BUCKET_NAME`. 

## 4. Security Preservation
- **Private Buckets**: The Cloudflare R2 bucket is strictly private. It cannot be accessed without the cryptographic signature generated by the backend.
- **Signed URL Expiry**: URLs expire tightly after 1 hour (3600 seconds).
- **IDOR Protection**: The redirect is only issued if the authenticated `userId` matches the `MemberDocument.userId` owner or possesses `DOCUMENT_VIEW` admin permissions.
- **SHA-256 Integrity**: Synchronous payload hashing remains functional at upload prior to SDK transmission.

## 5. Google Drive Legacy Preservation
The `GoogleDriveStorageProvider` was **not deleted**. It remains safely isolated within `google-drive-adapter.ts`. The previously configured Google Drive folder (`1B1krvvoY6Ooh93_uAUirDNrMDTOPVZfK`) retains its Restricted status. It serves as a documented legacy/temporary fallback provider, and the `storageProvider` flag within `MemberDocument` can easily track files persisting there until migration.

## 6. Migration Path
When ready to migrate Google Drive files to R2, a script can safely execute:
`Google Drive File (via storageObjectId) -> Download -> Verify against sha256 -> Upload to R2 -> Update DB storageProvider to 'R2'`. 

## 7. Result
The architectural mismatch between Vercel Serverless and 10MB document proxying has been fully resolved without sacrificing security, privacy, or vendor independence.
